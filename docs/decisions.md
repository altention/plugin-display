# display 插件：已定的需求和取捨

每條寫日期、誰定的（使用者或維護者）、原話或依據。

## 範圍

- 2026-10-20 使用者：插件從「LaTeX 轉圖片」擴大成 display：Discord 顯示不了的東西（數學式、表格、圖表、流程圖、差異、長文件、終端機輸出、SVG／HTML／PDF）都轉成圖片或其他格式再貼。盤點的 11 項全部要做（使用者：「這些都要做」）。
- 2026-10-20 維護者：display 只管 Claude 主動產出的顯示（skill 教 Claude 什麼時候用哪種格式＋`display` 指令）。機器人貼出前自動改寫回覆屬核心，由核心提供擴充點。
- 可互動的圖（縮放、hover）、儀表板不在範圍內。
- 一併涵蓋：小的純英數表格用程式碼區塊、有中文的轉圖；要複製的東西一項一個區塊；改動用 ```diff 區塊。

  - 說明寫在同一則訊息的文字裡，不另外先貼一則。

## 實作約束

- 全部免 sudo、不裝 node：同一個 headless Chrome＋npm 靜態 JS 檔，`--setup` 下載並校驗到 `~/.cache`。
- 對外一個介面：`display <檔案或 -> --kind … --post 頻道 --caption 說明`，一個 skill。
- 插件放在 `~/altention/plugins/display`（早期叫 latex，放在 `plugins/latex`）。

## 手機、iPad 上的行為（使用者 2026-10-20 實測）

- 複製：iPad、手機的程式碼區塊沒有複製鈕，長按會複製整則訊息的原文（連 ``` 一起）；單獨一則純文字複製出來是乾淨的。→ 要給人複製的東西，每一項用 `altention dc post` 單獨貼一則純文字。
- ```ansi、```diff 的顏色只有電腦版有，iPad、手機是白字。→ 有顏色的終端機輸出要轉圖；diff 區塊只放靠 +/- 也看得懂的短改動；要給人貼的程式碼不要放 diff（複製時 +/- 會跟著）。

## 部署與安全

- 2026-10-20 維護者：先只在一台開發機用，日常使用中收集問題；GitHub repo 建好後再給其他機器裝。
- 2026-10-20 維護者：`tex` 能用 `\input` 讀本機任何檔案 → **要修**，跟 HTML 放進沙盒同一個理由：轉出的圖會貼到 Discord，被塞進來的內容可以把這台的檔案（例如 token）排進圖裡貼出去。要求：tex 只讀得到自己的暫存資料夾和 Tectonic 的套件快取；擋不住的平台要明說並拒絕跑，不要默默放行。`plot`（跑給它的 Python）是設計上就會執行程式，先維持寫成已知限制。
- 2026-10-20 維護者：README 的需求只寫實際跑過的 Altention 版本以上，不往下寫到沒測過的版本。
- 2026-10-20 使用者（看完盲測後）：display **只處理 Discord 顯示不了的那一塊**（單一個公式、推導、表格、圖），文字盡量直接寫在 Discord 訊息裡，不要整份回答都畫成一張圖。原話：「display 應該只處理 dc 無法顯示的部分，而不是全都給他顯示」。排法選「文字＋圖分段貼」：照內容順序分成幾則，每則一段文字、底下接它講的那個公式或表格的小圖；最後的回覆放結論。整份畫成圖只留給使用者要求、或真的是一份要看整體排版的文件時。
- 2026-10-20 維護者：核心加上「機器人貼出最後回覆前交給插件改寫」的擴充點，display 這邊提供：`--segments --json` 印出依序的貼文 `{text, images}`，由機器人貼；`--for-bot` 模式遇到行內 `$x$` 不擋、照原樣留在文字裡（那時整則回覆已寫好，擋下來會整則貼不出去）。直接執行的 `--segments` 照舊擋。skill 要不要改成照常寫 Markdown、交給機器人，等擴充點上線、盲測後再問使用者。
- 2026-10-22 使用者：display 貼出的圖要能看原文，做法照 `/screen` 的 📝：使用者自己在圖上按 📝，機器人回一則可以複製的原文（例如 ```latex、```mermaid，註明是哪一種、用什麼畫的；太長就附檔）。**機器人不要先在圖上加 📝**（使用者原話：「這要會破壞畫面」），畫面跟現在一樣。display 這邊在每張圖旁邊留一份原文給機器人讀；Claude 自己貼的（`--segments`、`--post`）和機器人改寫的都要能用。
