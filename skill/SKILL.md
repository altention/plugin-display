# 在 Discord 顯示 Discord 顯示不了的東西

Discord 不排版 LaTeX、沒有表格、不畫圖，一則訊息最多 2000 字。

## 原則：只畫顯示不了的那一塊

- 回答的**文字照常是 Discord 訊息**：敘述、條列、粗體、程式碼區塊、結論都是。只把獨立的公式、推導、表格、圖表、流程圖畫成**小圖**，放在講它的那段文字底下。
- **不要把整份回答畫成一張圖**（文字也在圖裡，手機上要放大才看得到，也不能複製）。只有使用者要求整份轉成圖，或它本來就是一份要看整體排版的文件（講義、報告）時，才整份畫。
- 行內的簡單符號直接用 Unicode 寫在文字裡：x²、xᵢ、α、β、σ、θ、∇、∂、Σ、∫、≤、≥、≠、≈、→、⇒、×、·、√、∞、ℝ。**文字裡不要留 `$…$`**（Discord 會原樣顯示）。分數、好幾層上下標這類寫不成一行的，就獨立一行寫成 `$$…$$`，畫成圖。

## 先選格式

**Discord 本來就能顯示的，直接寫在訊息裡（不用畫）：**
- 要讓使用者複製的東西（指令、路徑、ID、設定值）：iPad、手機只能長按複製**整則訊息的原文**（程式碼區塊會連 ``` 一起複製），所以每一項**單獨貼一則純文字**：`altention dc post "$DCBOT_CHANNEL" "那一項"`，訊息裡只有它，不加說明、提示字元或 ```。先貼這些，最後的回覆再說明每一則是什麼。只是給人看、不用複製的程式碼照常放程式碼區塊。
- 一般程式碼：```語言 區塊（Discord 會上色）。超過約 40 行就附檔（`altention dc post "$DCBOT_CHANNEL" --file 檔案 "說明"`）。
- 短的改動（約 30 行以內）：```diff 區塊，其他行前面留一個空格。紅綠只有電腦版看得到，iPad、手機是白字，所以要靠開頭的 `+`、`-` 也看得懂；要靠顏色才看得清楚的就轉圖。複製時 `+`、`-` 會跟著一起，使用者要拿去貼的程式碼不要放在 diff 裡。超過 30 行的改動（重構、搬動）用 `diff` 畫成圖，不要用 ```diff 區塊。
- 樹狀結構（資料夾、決策樹）：程式碼區塊裡用 `├──`、`└──` 畫，中文放在右邊不影響對齊。
- **方塊加箭頭的框線圖不要用程式碼區塊畫**（`┌─┐`、`│`、`└─┘`、`──▶` 圍起來的架構圖、流程圖、連線示意）：框的右邊要靠每行等寬才對得齊，中文的寬度不是英文的整數倍，在 Discord 上一定歪，手機更糟。**用箭頭在程式碼區塊排的時序也一樣**：兩邊各一條 `|`、中間 `→`、`←` 來回的握手或請求流程，靠對齊才看得懂，有中文那行就歪。改用 `diagram`（Mermaid 的 flowchart；有先後的往返用 sequenceDiagram）畫成小圖，圖下面的說明、條列照常是文字。手機看，flowchart 預設 `TD`（直的）；`LR` 只用在 3 個節點以內（橫的長鏈在手機上字會小到看不清）。
- 小表格（5 欄以內、只有英文和數字）：程式碼區塊裡用空白對齊。**有中文就轉圖**（中文在程式碼區塊裡寬度不一，一定對不齊）。

**要畫成圖的：**
- 獨立的數學式、推導、矩陣、化學式（`\ce{H2O}`）
- 有中文或超過 5 欄的表格。使用者多半用手機看，圖最寬 720，欄位太多字會很小：超過 6 欄就拆成兩張表，或附 CSV 檔、圖只放重點幾欄
- 資料圖表（折線、長條、散佈、熱圖）
- 流程圖、時序圖、狀態圖、ER 圖、甘特圖、時間軸、心智圖；依賴圖、架構圖、元件怎麼連（不管大小，想用框線畫的都是這種）
- 長的程式差異（30 行以上），或使用者想看左右對照
- 有顏色的終端機輸出（測試結果、log）：```ansi 區塊只有電腦版有顏色，iPad、手機看到的是白字，顏色要緊就轉圖
- SVG、HTML 頁面、PDF 的某幾頁
- 使用者問某個 PDF、圖、頁面**長什麼樣子**：用 `pdf`（或 `image`）把那頁畫出來貼上，再用文字補說明；只用文字描述不夠。
- 使用者要在 Discord **看效果**的 HTML（卡片、頁面、樣式）：寫成 .html，用 `image` 畫成圖貼出。這比發佈 claude.ai Artifact 優先：只給連結的話，在 Discord 裡看不到效果。要互動（切換、hover）時，圖貼完再另外附連結。

很大的表（幾十列以上）或使用者要拿去用的資料：附 CSV 檔，最多再加一張前幾列的圖。

## 回答裡有公式、表格或流程圖：`--segments`（預設的做法）

把整份回答照平常的樣子寫成一份 Markdown（文字、`$$…$$`、表格、```mermaid 混在一起），然後：

```
~/altention/plugins/display/bin/display 回答.md --segments --post "$DCBOT_CHANNEL"
```

- 它照順序貼成幾則。Discord 會把一則訊息的文字排在圖**上面**，所以：每段文字和**緊跟在它後面**的圖放同一則（文字在上、圖在下；連在一起的幾張圖都放這一則，超過 10 張或 8 MB 才接到下一則）；前面沒有文字的圖、最後一張圖之後的文字各自一則。讀起來就是 引出公式的話 → 公式 → 下一段話 → 下一個公式 …，照平常的順序寫就對了。連在一起的幾個公式合成一張；超過 1900 字的文字會自動切開。
- **不重講前面貼過的內容**：最後一段和最後的回覆都不寫「上面兩張圖畫了…」「精簡版：」，也不把每段的重點再列成清單。最後一段照常寫最後一張圖之後要說的話，不限長短。**最後的回覆**只放一兩句結論或下一步，最多兩行，例如：「要細看 TIME_WAIT 怎麼調，可以再問。」先貼了要複製的幾則時，最後的回覆照上面說的說明每一則是什麼，不受兩行的限制。
- 文字裡留了公式記號（`$x$`、`$O(n)$`、行中間的 `$$…$$`、`\(…\)`）時它會停下來、什麼都不貼，並列出是哪幾個：照上面的原則改掉再跑。價錢（`$5`）不算。
- 不加 `--post` 只印出會怎麼貼（每則一行：`（文字）` 第一行，後面是接在文字下面的圖的路徑），可以先看。
- 表格最寬 720（手機上還讀得到）：很長的雜湊、網址、路徑會在格子裡換行。
- 圖表（Vega-Lite）、DOT、`tex`、`plot` 不在 `--segments` 裡：先用 `altention dc post "$DCBOT_CHANNEL" "那段文字"` 貼文字，再單獨畫那張圖貼上（見下）。

## 單獨畫一張

```
~/altention/plugins/display/bin/display 檔案 --post "$DCBOT_CHANNEL" --caption "一句說明"
```

- 貼回自己的頻道一律用 `"$DCBOT_CHANNEL"`（機器人開的對話裡就有，是這個頻道的 ID）：用名稱的話，機器人每則都要去查整個伺服器的頻道清單，Discord 一分鐘只准查幾次，連貼幾則就會卡住將近一分鐘。`--post` 後面不寫，也是 `$DCBOT_CHANNEL`。`$DCBOT_CHANNEL` 是空的時（用 /attach 接上的對話沒有它），所有寫 `"$DCBOT_CHANNEL"` 的地方改寫這個頻道的 ID 或名稱。貼到別的頻道才寫它的 ID（`altention dc read --map` 查）。貼到自己的頻道不會回到你這裡。
- 說明放 `--caption`：說明和圖在同一則（文字在上、圖在下），一則就好，不要先另貼一則說明。整份文件很長時會切成幾張，說明跟著第一張，後面的標 (2/3)…
- 種類照副檔名和內容自動判斷；判斷不出來或要指定時加 `--kind`（見下）。從 stdin 讀用 `-`，短的用 `-e '…'`（含 `$` 用單引號）。
- 不加 `--post` 只印出圖的路徑（一行一張）。
- 最後的文字回覆照常寫結論，不要再把同一份原始碼貼一次（使用者要原文時才給，放程式碼區塊）。

## 各種輸入怎麼寫

**`doc`（.md、.txt、.csv；`--kind math`、`table` 也是它）**：Markdown。
- 行內公式 `$...$` 或 `\(...\)`；獨立一行 `$$...$$`、`\[...\]`，或直接寫 `\begin{align*}...\end{align*}`（equation、gather、multline、alignat 也行）。KaTeX 支援的都可以（矩陣、cases、`\mathbb`、`\operatorname`、`\ce`）；`\newcommand` 不行，直接展開。
- 價錢 `$5`（`$` 後面接數字或空白）不會被當成公式；真的要一個單獨的 `$` 寫 `\$`。程式碼區塊和 `` `行內程式碼` `` 裡的 `$` 都不動。
- 表格用 Markdown 的 `|` 表格（第二列 `|---|--:|:-:|` 決定靠左、靠右、置中），格子裡可以有公式。CSV／TSV 用 .csv／.tsv 檔，或從 stdin 給時加 `--kind table`（不會自己猜）。
- 可以放 ```mermaid 區塊，會畫在文件裡。
- HTML 標籤照字面顯示，不會執行。

**`chart`（.json）**：一份 Vega-Lite spec，資料直接寫在 `data.values`（不能讀檔案或網址）。顏色、字型、深底都會自動套，不用設。

```json
{"title": "訓練損失", "data": {"values": [{"step": 1, "loss": 2.3, "model": "A"}, {"step": 2, "loss": 1.1, "model": "A"}]},
 "mark": {"type": "line", "point": true},
 "encoding": {"x": {"field": "step", "type": "quantitative", "axis": {"tickMinStep": 1}},
              "y": {"field": "loss", "type": "quantitative"}, "color": {"field": "model"}}}
```

資料很多、要用 numpy／pandas 算、或是科學圖（子圖、誤差帶、對數軸）：改寫一個 matplotlib 腳本，用 `--kind plot`（見下）。

**`diagram`（.mmd）**：Mermaid 原始碼（flowchart、sequenceDiagram、gantt、timeline、mindmap、classDiagram、erDiagram、stateDiagram-v2…）。節點文字有括號或特殊符號就用引號：`A["f(x) 的值"]`。

**`graph`（.dot、.gv）**：Graphviz DOT（`digraph { a -> b }`）。節點多、要自動排版的依賴圖用它；顏色、字型會自動套。

**`diff`（.diff、.patch）**：unified diff（`git diff` 的輸出），畫成 GitHub 那樣的紅綠。預設單欄；左右對照加 `--side-by-side`（很寬，只在行短時用）。

**`term`（.log、.ansi）**：有 ANSI 顏色碼的終端機輸出。要保留顏色，產生輸出時加 `--color=always` 之類的選項（`pytest --color=yes`、`git -c color.ui=always diff`）。

**`image`（.svg、.html）**：SVG 或 HTML 頁面轉成 PNG。HTML 在沙箱裡跑，不能讀這台的檔案、不能連網、不能跳到別頁，所以圖片要內嵌（data:）。畫出來跟瀏覽器裡一樣（沒設背景就是白底），預設寬 1000，最寬 2000；長的頁面切成幾張，超過 5000 的部分不畫（stderr 會說）：太長的頁面自己分段，或轉成 PDF 用 `pdf`。

**`pdf`**：PDF 的頁面，`--pages 2-4`（預設前三頁，一次最多 20 頁）。

**`tex`（.tex）**：KaTeX 做不到的（tikz、`tabular`、其他套件）才用。輸入是 LaTeX 文件的內容（`\begin{document}` 裡面那段），要套件用 `--preamble '\usepackage{tikz}'`。第一次在一台機器上跑要下載 TeX 套件（幾分鐘），之後每張約 2–5 秒。在沙箱裡跑：讀不到暫存資料夾以外的檔案（`\input` 只能用文件裡的內容）；這台沒有沙箱時會說「不畫 tex」，那就改用 `doc`（KaTeX）。

**`plot`（.py）**：matplotlib 腳本。畫完把圖留著就好（不要 `plt.close()`、`savefig`、`show`）；有幾個 figure 就出幾張。深底、配色、中文字型會自動套。

## 出錯時

- `畫不出來：…` 或 `公式錯誤：…`：會說哪一個式子、哪裡錯（未定義的指令、沒配對的 `$`、Mermaid／DOT 語法錯）。改好再跑。KaTeX 真的不支援的改用 `--kind tex`。
- `這台畫 … 還缺…`：每一行是缺的東西和怎麼補。寫「跑 … --setup …」的直接照跑（tectonic、plot 安裝時不裝，第一次用到才裝，要等一下；工具都裝在 `~/.cache/altention-display`，不用 sudo）；要 sudo 或 brew 的系統工具（Chrome、poppler、中文字型、python3-venv）不要自己裝，把那一行轉告使用者。`--check` 看全部。
- 圖太寬看不清楚：`--width 520`（文件類預設 720）。

## 底色

預設深底（Discord 深色主題的底色 `#2b2d31`），淺色主題下看起來是一張深色卡片，也清楚。使用者要白底時加 `--theme light`。
